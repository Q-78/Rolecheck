# RoleCheck：一页课题说明

**暂定英文题目：**  
**RoleCheck: Plug-and-Play Multi-Agent Initialization Auditing and Minimal Repair via Counterfactual Role-Value Prediction**

**版本：** v0.1  
**日期：** 2026-08-01  
**状态：** 课题定义稿；尚未进入具体实验设计与工程执行。

---

## 1. 背景与问题

LLM 多智能体系统的初始化方法，正在从人工指定固定角色，发展到根据任务自动生成 Agent 数量、角色、职责和通信结构。代表性工作如 AgentInit 关注任务相关性、专业性与团队多样性，ARG-Designer 进一步联合生成团队成员与通信拓扑；MASS、MASPO 等工作则说明角色 Prompt 和系统结构均可被自动优化。

但是，**初始化器生成了“看起来合理”的角色，不等于这些角色对当前团队真正有价值**。一个角色可能：

- 与任务语义相关，但与现有成员高度冗余；
- 个体能力较强，却因协议或聚合方式干扰团队；
- 当前贡献较低，但通过小幅职责修订即可产生价值；
- 被静态审计判断为“重复”，却因模型异构性提供独特信息；
- 角色规范没有明显错误，但其输出无法被下游角色或聚合器利用。

因此，现有系统仍缺少一个位于**初始化器之后、正式执行之前**的角色准入与修复层。

---

## 2. 核心观点

> **角色质量不是角色自身的固定属性，而是由任务、其他团队成员和执行协议共同决定的关系属性。**

普通角色评分关注：

\[
Q(r_i)
\]

RoleCheck 关注：

\[
Q(r_i \mid x, C_{-i}, \pi)
\]

其中：

- \(x\)：当前任务；
- \(r_i\)：被审计角色；
- \(C_{-i}\)：除该角色外的团队配置；
- \(\pi\)：通信、执行和聚合协议。

---

## 3. 两类操作性反事实价值

### 3.1 角色保留价值

对初始化团队 \(C\) 中的角色 \(a_i\)，定义：

\[
\Delta_i^{keep}
=
U(x,C,\pi)
-
U(x,C\setminus\{a_i\},\pi)
\]

它回答：

> 在其他条件保持不变时，保留该角色相对于移除该角色，为团队带来了多少效用？

- \(\Delta_i^{keep}>0\)：角色具有正贡献；
- \(\Delta_i^{keep}\approx 0\)：角色可能冗余；
- \(\Delta_i^{keep}<0\)：角色可能具有干扰性。

### 3.2 候选修复价值

对角色 \(r_i\) 的有限候选修复版本 \(r'_{ik}\)，定义：

\[
\Delta_{ik}^{repair}
=
U(x,C_{i\leftarrow r'_{ik}},\pi)
-
U(x,C,\pi)
\]

它回答：

> 用指定修复版本替换原角色，是否比保持原团队更好？

RoleCheck 不直接预测“任意重写”的价值，而是先生成有限修复候选，再分别预测其收益与不确定性。

---

## 4. 方法概览

```text
已有初始化器
    ↓
初始团队配置 C
    ↓
Role Contract Normalizer
    将不同框架的自然语言角色转为统一合同
    ↓
Role Defect Auditor
    检查内在缺陷、团队关系缺陷和协议兼容性
    ↓
Counterfactual Role-Value Predictor
    预测保留价值、候选修复价值与不确定性
    ↓
Risk-Aware Minimal Intervention
    KEEP / REWRITE / REMOVE
    ↓
修复后的团队 C'
    ↓
原 MAS 执行框架
```

系统遵循“最小干预”原则：

- 不重新设计整个团队；
- 不修改没有可靠异常证据的角色；
- 不改变无关的模型、工具、拓扑和协议；
- 没有可靠正收益时默认保留；
- 只有在保守收益为正时才重写；
- 只有在角色可靠地表现为有害时才移除。

## 5. RoleCheck 与相邻工作的区别

| 相邻方向 | 主要问题 | RoleCheck 的区别 |
|---|---|---|
| AgentInit / ARG-Designer | 应生成怎样的团队 | 审计初始化器已经生成的角色 |
| MASS / MASPO / MAPRO | 如何搜索或联合优化 Prompt | 重点预测“改谁、是否值得改、哪个候选值得采用” |
| 文本反馈 MAS 优化 | 根据执行反馈定位低表现角色并重写 | 以团队条件反事实价值为核心决策信号 |
| AgenTracer / AgentLocate | 失败发生后定位责任 Agent 和步骤 | 在当前任务完整执行前评估潜在价值与风险 |
| Agents that Matter | 通过实际移除测量 Agent 贡献 | 目标是在当前任务上提前预测贡献 |
| CCPO / LEMON | 用反事实信用优化策略或编排器 | RoleCheck 是外部审计与最小干预层，不训练完整协作策略 |

## 6. 预期贡献

1. **新问题定义：**提出初始化后的、当前任务执行前的反事实角色审计问题。
2. **双层建模：**区分“角色缺陷诊断”和“真实团队价值预测”，避免把语义异常直接等同于应当干预。
3. **价值驱动的最小修复：**同时预测角色保留价值和有限修复候选价值，仅在可靠收益为正时修改。
4. **框架无关接口：**通过统一 Role Contract 连接不同初始化器和运行时。
5. **风险控制：**使用不确定性和拒绝判断机制降低健康角色被误改的概率。

---

## 7. 最大风险

- 执行前信息可能不足以准确预测当前任务上的边际价值；
- 修复候选价值比保留价值更难预测；
- 低贡献可能主要来自基础模型能力，而不是角色设计；
- 交互式 MAS 中，移除角色会改变后续上下文，反事实量依赖具体干预协议；
- “可插拔”若需要为每个初始化器单独训练或改规则，将难以成立；
- 如果定向修复不优于通用重写，论文可能应收缩为角色价值预测或角色审计 Benchmark。

---

## 8. 暂不主张

当前阶段不主张：

- RoleCheck 是首个角色优化方法；
- 所定义的增益是普遍因果效应；
- 方法适用于所有 MAS、所有协议和所有任务；
- 完全无需任何历史执行数据；
- 能同时优化角色、模型、工具、拓扑和通信；
- 可插拔性已经得到证明。

---

## 9. 一句话摘要

> RoleCheck 是一个位于 MAS 初始化器和执行框架之间的角色审计层：它把初始化角色转化为统一合同，诊断潜在缺陷，在当前任务完整执行前预测角色的操作性反事实保留价值与候选修复价值，并以不确定性感知的方式决定保留、最小重写或移除。
