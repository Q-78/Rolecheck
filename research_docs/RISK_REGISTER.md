## 风险处理优先级

### 立即控制

- R-007：通过干预协议冻结控制；
- R-011：在正式数据管线开始前加入泄漏审计；
- R-014：Manifest、seed 与哈希从仓库第一天开始记录；
- R-017：通过候选 Schema 与字段白名单控制；
- R-018：Mock Runtime 输出必须显式标记。

### Gate 1 前必须回答

- Benchmark 是否产生足够的正、零、负价值样本；
- 移除协议是否可执行、可复现且不引入隐藏补偿；
- 多 seed 下标签稳定性是否可接受。

### Gate 2 前必须回答

- Strict 模式是否存在超越简单基线的预测信号；
- 是否存在当前任务信息泄漏；
- 合同解析风险是否能被识别并驱动 abstention。

### Gate 3 前必须回答

- 修复候选是否具有足够多样性和真实正增益；
- 排序器是否优于缺陷规则、编辑距离或生成器原始排序；
- 健康角色误改率和修复后下降率是否受控。

## 更新规则

每周至少检查一次：状态、触发信号、已发生事件、缓解效果和剩余风险。任何论文主张升级前，必须检查对应风险是否仍为未控制高风险。
